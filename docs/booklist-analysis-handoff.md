# 达人书单分析 Handoff

这份文档用于交接“达人书单/路线”分析工作。目标不是单纯 OCR 识别书名，而是把达人资料整理成系统可用的数据：达人说明书、路线阶段、阶段书单、原图证据、导入 CSV 规范和前端可浏览内容。

## 工作目标

每个达人最终至少产出四类内容：

1. 达人说明书：写给 AI 和后续整理者看的方法论摘要，放入 `docs/knowledge/`，并入库为 `RecommendationSourceKnowledge`。
2. 路线/书单结构：区分年龄段书单、路线型书单、等级参照、著作资料，不把所有图片简单混成一个列表。
3. 推荐条目：每一次“某达人在某年龄/阶段推荐某套书或素材”都保留一条推荐记录，支持作品详情反查出现在哪些达人路线里。
4. 原图证据：原图按正确顺序保存并绑定到具体路线/书单详情页，可在前端“整理版 / 原图”之间切换。

## 总体步骤

### 1. 清点资料

先清点 `booklist/达人名/` 目录下有哪些文件：

- `txt/md`：达人介绍、路线说明、用户摘录、著作笔记。
- 图片：书单原图、路线图、截图。
- PDF/电子书/长文：通常先只做资料登记，除非当前阶段明确要解读。

检查图片数量是否和用户预期一致。比如庆爸常规路径应为 18 张，如果页面只显示 7 张，要先解决排序/同步/文件缺失问题，再继续分析。

### 2. 建立达人说明书

先读文字介绍，不要急着入库书名。说明书需要回答：

- 这个达人是谁，方法核心是什么。
- 他的路线适合谁，不适合谁。
- 推进路线依赖哪些判断变量，例如年龄、听力词汇、小小优趣 phase、AR、蓝思、牛津树等级、输入小时数、是否能裸听。
- 哪些内容是书单条目，哪些只是操作动作。
- 同一套书跨年龄或跨阶段重复出现时，应该保留哪些上下文。

说明书放在 `docs/knowledge/{source-slug}.md`。图片逐页解读笔记如果很长，可以单独放一个 `docs/{source-slug}-reading-notes.md`，再作为 `image_reading` 知识条目入库。

### 3. 给资料分型

不要只按文件夹名机械判断，要读内容后分型：

| 类型 | 入库方式 | 例子 |
| --- | --- | --- |
| 年龄段书单 | `list_type=age_band`，阶段可用年龄段 | 香蕉妈妈 2-3 岁、3-4 岁书单 |
| 路线型书单 | `list_type=route`，必须拆阶段 | 庆爸常规路径、大循环、桥梁路线 |
| 等级参照 | `list_type=level_map` 或路线补充 | 牛津树等级、AR/蓝思参照 |
| 著作资料 | publication + knowledge，Phase 2 再深入拆书单 | 盖兆泉《做孩子最好的英文学习规划师》 |
| 纯介绍 | profile + knowledge | 达人自述、账号介绍 |

### 4. 读图和排序

原图顺序优先级：

1. 图片里明确的 Page1/Page2/第几页。
2. 文件名中的序号。
3. 内容逻辑顺序，例如概况 -> 阶段说明 -> 素材清单 -> 操作方法。
4. 都无法判断时，在知识笔记里标记“不确定”，不要硬编顺序。

需要时建立 `order.json` 来校准图片顺序。用户说“图上有顺序”时，必须优先按图中文字顺序，不要只按文件系统排序。

### 5. 抽取阶段

路线型达人必须先抽阶段，再抽条目。每个阶段至少记录：

- `title`：阶段名。
- `stage_order`：阶段顺序。
- `age_min_months` / `age_max_months`：如果资料里有年龄。
- `hours`：输入时长或累计时长。
- `entry`：准入门槛。
- `advance`：晋级标准。
- `notes`：重要解释、限制和使用方法。
- `source_page_order`：对应原图页码。

阶段不是书单本身。比如“先裸听后回看”“去字幕观看”“降速 0.9x”是操作方法，只能进入阶段说明或 `reminder`，不能作为书架条目。

### 6. 抽取书单/素材条目

每个阶段要继续抽“这一阶段到底用哪些书、分级、动画、音频、APP、资源”。推荐按角色分组：

| role | 含义 |
| --- | --- |
| `mainline` | 主线素材 |
| `supplement` | 辅线/补充素材 |
| `extension` | 兴趣拓展 |
| `fallback` | 备选或调整策略 |
| `test_material` | 测试材料 |
| `prerequisite` | 前置条件 |

素材类型建议：

| material_type | 含义 |
| --- | --- |
| `picture_book` | 绘本 |
| `graded_reader` | 分级读物 |
| `bridge_book` | 桥梁书 |
| `early_chapter` | 初章 |
| `chapter_book` | 章节书 |
| `animation` | 动画 |
| `app` | APP/平台 |
| `audio` | 音频 |
| `resource` | 台词本、练习册、资料包 |
| `method` | 方法说明 |

书、分级、桥梁书等可以进入 `Collection`；动画、APP、音频、方法通常作为路线素材保存，不进入作品书架。

### 7. 保留提醒和证据

图片里任何“强烈推荐、进阶、3.5 岁以上、虚构部分、可挑选、任选、建议后加入、不要跨难度”等都要保留。字段建议：

- `emphasis`：强推、重点推荐。
- `progression`：进阶、拓展、后续可读。
- `reminder`：年龄提醒、难度提醒、使用限制。
- `role`：主线/补充/测试/拓展。
- `material_type`：素材类型。
- `source_page_id`：绑定原图页。
- `raw_text`：完整原文备注。

不要因为已经归并成同一本书，就丢掉不同达人、不同年龄段、不同阶段的提醒。

### 8. 生成或校验 CSV

用户自助导入其它达人时，需要按 `docs/import-csv-format.md` 整理 CSV。内部基础达人可以由 seed 代码导入，但字段口径应和 CSV 保持一致。

最小必填字段：

- `source_name`
- `list_title`
- `raw_title`

路线型书单强烈建议补齐：

- `stage_title`
- `stage_order`
- `position`
- `role`
- `material_type`
- `source_image_filename`
- `reminder` / `raw_text`

### 9. 入库与验证

每轮整理后至少做四个验证：

1. 运行 seed 或导入接口，确认没有报错。
2. 查数据库或 API，确认路线阶段数、条目数、原图页数符合预期。
3. 打开前端达人详情，确认达人简介不是密密麻麻原文，而是提炼说明。
4. 打开某条路线详情，确认“整理版”有阶段书单，“原图”能看清对应原图。

## 常见错误

- 只 OCR 书名，不读达人方法论。
- 把操作动作当成书单条目，例如“去字幕观看”“裸听”“回看动画”。
- 同一套书跨阶段出现时直接合并，导致作品详情不能反查推荐场景。
- 图片不按图上 Page 顺序排，只按文件名排。
- 地图横坐标用自适应宽度硬摆卡片，导致卡片位置随屏幕变化而错位。
- 原图放在单独资料块里，和具体路线脱离，用户无法对照整理版。
