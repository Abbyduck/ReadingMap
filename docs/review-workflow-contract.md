# 审核工作台稳定行为约定

本文件是已确认的产品行为基线，不表示代码永远不能改。修 bug、优化实现可以进行，但不得悄悄改变以下对用户可见的行为。若确需变更，必须事先说明具体会改哪一条、原因和影响，等用户确认后再动。

## 推荐事实

- 一条 `reading_list_item` 就表示来源在该书单/阶段推荐了该 Entity；不再存“弱/普通/强”数字档位。
- 正式表只存 `is_strong_recommendation` 与 `recommendation_emphasis_text`。`recommendation_strength` 和推荐分数不是正式数据库字段；旧导入数据的兼容读取不能被误当成新字段。
- 仅来源明确出现强烈推荐、重点推荐、必读等强调语义时自动勾选强推；人工可修改。不能凭排序、评分、出现次数或视觉需要推测强推。
- `reading_list_item` 只指向当前来源真正推荐的对象。Research 被动发现的父级、同级、成员只用于补齐 Catalog 结构，不能变成这条来源的推荐。

## 草稿与证据

- Catalog Draft、推荐语、备注、图片选择等人工修改不能因刷新 Research、采集商品/官网或切换审核项而被无提示覆盖。保存草稿由明确操作触发；表单中的 Ctrl+S 等于“保存草稿”。
- 来源原文与官网/商品证据要保留可追溯关系。不要把“原图第 N 页第 N 行”这类定位信息塞进有意义的备注。
- 官方资料搜索必须在可被采集流程监测的同一个浏览器会话里打开；只打开 Google 结果但未发现可采集官网页时，不得宣称已采集。打开匹配的官网详情后应自动采集，失败必须给出可见原因。
- 分类优先用官方分类；官方未标注时可依据有来源的简介归纳为草稿，供人工审核，不能伪称官方标注。

## 结构与审核交互

- 系列父级、同级和成员使用紧凑结构树 + 右侧 Inspector；正常节点默认随整体提交，只有疑似匹配、冲突或缺失证据才打扰审核人。不得恢复逐节点大卡片和逐个确认弹窗。
- 名称中的系列标记也属于 Research 线索，但线索不等于已核实关系；需要官方或其他可靠证据后才建立正式父子关系。
- `collection_items` 只保存直接 membership，不自动保存祖先关系。写入 Catalog 应是事务：关键步骤失败则回滚。
- 图片可从任一候选图切换封面，封面 radio 叠在图片左上角；详情图 checkbox 独立保留。切换不应导致全部控件短暂禁用或页面滚回顶部。

## 每次改动的回归检查

1. 刷新审核页没有泛化 500；若请求失败，错误至少指出请求方法与路径。
2. 官方搜索实际打开可监测的搜索页，官网详情识别与自动采集没有静默失效。
3. 保存/刷新后人工草稿和图片选择不丢失；推荐强推的自动识别和人工修改都有效。
4. 结构树的推荐对象与被动 Research 对象严格区分，Catalog 只写直接关系。
